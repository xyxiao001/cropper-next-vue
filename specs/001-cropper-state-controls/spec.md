# 功能规格：裁剪状态与交互控制

**功能分支**：`codex/feature-planning`

**创建日期**：2026-08-20

**状态**：草案

**输入**：新增 `reset()`、`change` 结构化状态事件，以及禁止移动和缩放的交互开关。

## 用户场景与测试

### 用户故事 1：一键恢复初始裁剪状态（优先级：P0）

作为组件使用者，我希望在用户移动、缩放、旋转或调整裁剪框后，通过一次调用恢复当前图片的初始裁剪状态，而不重新加载图片。

**优先原因**：表单撤销、重新编辑和重复尝试都需要可靠的恢复入口。

**独立测试**：加载图片后记录初始状态，执行移动、缩放、旋转和裁剪框调整，再调用重置；最终状态应与当前配置下的初始状态一致，且图片不重新加载。

**验收场景**：

1. **假如** 图片已经完成加载并被移动、缩放和旋转，**当** 使用者调用 `reset()`，**那么** 图片位置、缩放和旋转恢复到当前 props 对应的初始状态。
2. **假如** 裁剪框位置或大小已通过公开方法改变，**当** 使用者调用 `reset()`，**那么** 裁剪框恢复到当前 `cropLayout` 配置对应的初始大小和位置。
3. **假如** 当前存在待执行的边界回弹，**当** 使用者调用 `reset()`，**那么** 重置结果保持稳定，不再被先前交互的回弹覆盖。
4. **假如** 当前没有已加载图片，**当** 使用者调用 `reset()`，**那么** 组件状态保持不变。

---

### 用户故事 2：订阅完整裁剪状态（优先级：P0）

作为组件使用者，我希望在裁剪状态变化时收到结构化数据，以便同步外部表单、调试面板或保存编辑状态，而不需要解析实时预览内容。

**优先原因**：结构化状态是外部业务与裁剪器可靠联动的基础。

**独立测试**：监听 `change` 事件，依次加载、移动、缩放、旋转、调整裁剪框和重置，验证每次事件都反映对应操作完成后的完整状态。

**验收场景**：

1. **假如** 图片完成初始布局，**当** 组件首次形成可用裁剪状态，**那么** 触发一次 `change` 事件。
2. **假如** 图片位置、缩放、旋转或裁剪框发生变化，**当** 该次状态更新完成，**那么** `change` 事件返回同一时刻的完整图片状态和裁剪框状态。
3. **假如** 使用者调用 `reset()`，**当** 重置完成，**那么** `change` 事件返回重置后的状态。
4. **假如** 使用者只执行导出且裁剪状态未变化，**当** 导出完成，**那么** 不因导出额外触发 `change`。

---

### 用户故事 3：关闭用户移动或缩放（优先级：P0）

作为组件使用者，我希望分别关闭拖拽移动和手势缩放，以支持只读预览、仅按钮控制和不同终端的交互配置。

**优先原因**：交互权限控制能够让现有组件覆盖更多集成场景，同时保持现有默认体验。

**独立测试**：分别切换 `movable` 和 `zoomable`，验证鼠标与触摸交互是否被阻止，并验证对应实例方法仍能改变状态。

**验收场景**：

1. **假如** `movable` 为 `false`，**当** 用户使用鼠标或单指拖拽图片或裁剪框，**那么** 图片和裁剪框位置均不变化。
2. **假如** `zoomable` 为 `false`，**当** 用户使用鼠标滚轮或双指缩放，**那么** 图片缩放和位置均不变化。
3. **假如** `movable` 或 `zoomable` 为 `false`，**当** 使用者调用移动、裁剪框、缩放或重置相关实例方法，**那么** 实例方法仍按原有规则执行。
4. **假如** 未传入两个开关，**当** 用户拖拽或缩放，**那么** 交互行为与当前版本一致。
5. **假如** 运行时切换两个开关，**当** 用户开始下一次交互，**那么** 新配置立即生效且无需重新加载图片。

### 边界情况

- `reset()` 必须使用调用时最新的 `img`、`cropLayout`、`mode` 和 `defaultRotate` 配置计算初始状态。
- 当 `centerBox` 或 `centerWrapper` 开启时，重置后的状态仍满足对应边界规则。
- `movable=false` 不影响双指缩放中由缩放锚点产生的必要位置调整；是否允许双指缩放只由 `zoomable` 决定。
- `zoomable=false` 不改变公开缩放实例方法，也不改变缩放上下界和回弹规则。
- 新 `change` 事件不替代或改变现有 `real-time`、`realTime`、`img-load` 和 `img-upload` 事件。

## 需求

### 功能需求

- **FR-001**：组件必须公开 `reset()` 实例方法。
- **FR-002**：`reset()` 必须恢复当前图片在最新 props 配置下的初始图片位置、缩放和旋转状态。
- **FR-003**：`reset()` 必须恢复当前 `cropLayout` 对应的初始裁剪框大小和位置。
- **FR-004**：`reset()` 不得重新请求、读取或解码当前图片。
- **FR-005**：`reset()` 完成后，先前交互产生的待执行回弹不得再次改变重置结果。
- **FR-006**：组件必须公开 `change` 事件，事件数据包含 `image: { x, y, scale, rotate }` 和 `crop: { x, y, width, height }`。
- **FR-007**：首次可用裁剪状态以及图片移动、缩放、旋转、裁剪框变化和重置完成后，必须触发 `change`。
- **FR-008**：导出操作本身不得触发 `change`。
- **FR-009**：组件必须新增 `movable` prop，类型为布尔值，默认值为 `true`。
- **FR-010**：`movable=false` 必须禁止鼠标和单指拖拽引起的图片与裁剪框移动。
- **FR-011**：组件必须新增 `zoomable` prop，类型为布尔值，默认值为 `true`。
- **FR-012**：`zoomable=false` 必须禁止鼠标滚轮和双指手势引起的缩放。
- **FR-013**：`movable` 和 `zoomable` 不得限制任何公开实例方法。
- **FR-014**：两个 prop 在运行时变化后，必须从下一次用户交互开始生效，无需重新加载图片。
- **FR-015**：现有事件、边界限制、缩放速度、缩放锚点和公开方法行为必须保持不变。
- **FR-016**：新增 API 必须提供类型声明、中文和英文文档，并在首页与全功能配置页提供开关或操作示例。

### 关键实体

- **裁剪状态**：由图片状态和裁剪框状态组成，是 `change` 事件的完整数据。
- **图片状态**：图片在容器坐标系中的 `x`、`y`、`scale` 和 `rotate`。
- **裁剪框状态**：裁剪框在容器坐标系中的 `x`、`y`、`width` 和 `height`。

## 成功标准

### 可衡量结果

- **SC-001**：在所有受支持的移动、缩放、旋转和裁剪框调整组合后，一次 `reset()` 调用即可恢复与初始状态逐字段一致的结果。
- **SC-002**：所有会改变裁剪状态的公开操作和用户交互，均能通过一次 `change` 回调取得完整且相互一致的 8 个状态字段。
- **SC-003**：关闭 `movable` 或 `zoomable` 后，对应的鼠标和触摸交互阻止率为 100%，而相关实例方法成功率保持 100%。
- **SC-004**：不传入新 props 时，现有自动化测试中的交互和导出行为保持全部通过。
- **SC-005**：使用者无需读取预览 URL、HTML 或样式字符串即可保存当前裁剪状态。

## 假设

- `reset()` 表示恢复当前 props 配置计算出的初始状态，不是恢复组件首次挂载时已经过期的配置。
- `reset()` 不承担撤销历史功能，仅提供单一的初始状态恢复能力。
- `movable` 同时控制图片拖拽和裁剪框拖拽，不拆分为两个独立开关。
- `zoomable` 同时控制鼠标滚轮和双指缩放，不拆分为两个独立开关。
- 结构化状态采用当前容器坐标系；本功能不新增原图像素坐标输出或状态恢复输入方法。
