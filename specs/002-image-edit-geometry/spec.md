# 功能规格：图片编辑与原图几何

**功能分支**：`codex/feature-planning`

**创建日期**：2026-08-20

**状态**：草案

**输入**：新增缩放上下限、水平/垂直翻转，以及获取原图裁剪坐标能力。

## 澄清记录

### 2026-08-20

- Q：缩放上下限与初始布局或边界覆盖要求冲突时哪一方优先？ → A：初始布局先遵守上下限；`centerBox` / `centerWrapper` 的边界覆盖要求优先，必要时将有效上限提升到边界所需比例。
- Q：图片旋转后水平/垂直翻转相对哪个坐标轴？ → A：相对屏幕可见方向，水平始终左右镜像，垂直始终上下镜像。
- Q：任意角度旋转和翻转后如何返回原图裁剪坐标？ → A：返回原图四角点、外接矩形、源图尺寸以及旋转/翻转信息。

## 用户场景与测试

### 用户故事 1：限制图片缩放范围（优先级：P1）

作为头像、证件照或固定版式业务的组件使用者，我希望设置允许的最小和最大缩放比例，避免终端用户把图片无限放大或缩得过小。

**优先原因**：缩放范围直接决定裁剪结果是否满足业务可用性要求。

**独立测试**：分别通过滚轮、双指手势和公开缩放方法尝试超过上下限，验证最终缩放比例始终停留在允许范围内；未配置时保持当前行为。

**验收场景**：

1. **假如** 已配置最小缩放比例，**当** 用户或实例方法继续缩小时，**那么** 图片停留在最小比例。
2. **假如** 已配置最大缩放比例，**当** 用户或实例方法继续放大时，**那么** 图片停留在最大比例。
3. **假如** 未配置新的缩放范围，**当** 用户执行现有缩放操作，**那么** 行为与当前版本一致。
4. **假如** 运行时修改缩放范围，**当** 发起下一次缩放操作，**那么** 新范围立即生效。

---

### 用户故事 2：水平或垂直翻转图片（优先级：P1）

作为图片编辑业务的组件使用者，我希望通过实例方法水平或垂直翻转图片，并让预览、导出和状态事件保持一致。

**优先原因**：翻转是与旋转互补的常见基础编辑能力。

**独立测试**：对同一图片依次执行水平翻转、垂直翻转、旋转和重置，验证画面、导出结果及结构化状态逐步反映对应变化。

**验收场景**：

1. **假如** 图片已加载，**当** 调用水平翻转方法一次，**那么** 图片左右镜像；再次调用恢复原方向。
2. **假如** 图片已加载，**当** 调用垂直翻转方法一次，**那么** 图片上下镜像；再次调用恢复原方向。
3. **假如** 图片已翻转，**当** 获取实时预览、结构化状态或导出结果，**那么** 三者都反映相同翻转状态。
4. **假如** 图片已翻转，**当** 调用 `reset()`，**那么** 两个翻转状态恢复为未翻转。
5. **假如** 当前没有已加载图片，**当** 调用翻转方法，**那么** 组件状态保持不变。

---

### 用户故事 3：获取原图裁剪坐标（优先级：P1）

作为需要服务端裁剪或保存编辑参数的组件使用者，我希望直接读取裁剪区域在原始图片像素坐标系中的几何信息，而不解析预览样式或导出图片。

**优先原因**：原图坐标是服务端处理和跨终端复现裁剪范围的基础。

**独立测试**：在移动、缩放、任意角度旋转及水平/垂直翻转组合下读取坐标，并与对应原图像素点逐项比对；读取行为不改变当前裁剪状态。

**验收场景**：

1. **假如** 图片已加载且未旋转或翻转，**当** 获取原图裁剪坐标，**那么** 返回值与当前裁剪框映射到原图后的像素区域一致。
2. **假如** 图片存在缩放、旋转或翻转，**当** 获取原图裁剪坐标，**那么** 返回值仍能无歧义描述原图中的实际裁剪区域。
3. **假如** 只读取原图裁剪坐标，**当** 读取完成，**那么** 图片、裁剪框及 `change` 事件次数均不变化。
4. **假如** 当前没有已加载图片，**当** 获取原图裁剪坐标，**那么** 明确返回不可用结果。

### 边界情况

- 初始布局和 `reset()` 先遵守缩放上下限；当边界覆盖所需比例更高时，边界要求优先，有效上限随有效下限提升到该比例。
- 缩放上下限相等时，所有缩放入口都固定在该比例。
- 假设使用者只传入正数且最小值不大于最大值；无效配置的校验与兼容不在本功能范围内。
- 图片旋转后，水平和垂直翻转仍相对屏幕可见方向执行，并以图片显示中心为翻转中心。
- 连续执行同一方向翻转两次必须恢复原方向，且不产生累计几何误差。
- 原图裁剪坐标返回按裁剪框左上、右上、右下、左下顺序映射的四角点，同时返回四角点外接矩形、源图尺寸及当前旋转/翻转信息。
- 当裁剪框超出图片覆盖范围时，返回未经裁切的真实映射坐标，允许点位超出源图边界。
- “原图”指经过浏览器方向校正后、进入裁剪器的完整源图像素坐标系；不返回压缩预览图坐标。

## 需求

### 功能需求

- **FR-001**：组件必须新增 `minScale` prop，表示允许的绝对最小缩放比例，默认保持当前最小比例 `0.01`。
- **FR-002**：组件必须新增 `maxScale` prop，表示允许的绝对最大缩放比例，默认不设置有限上限。
- **FR-003**：鼠标滚轮、双指手势、`zoomIn()`、`zoomOut()` 和 `changeScale()` 必须遵守同一组最新缩放上下限。
- **FR-004**：缩放达到边界后，继续同方向缩放不得改变图片比例或位置。
- **FR-005**：运行时修改 `minScale` 或 `maxScale` 后，必须从下一次缩放操作开始生效，且不得重新加载图片。
- **FR-006**：初始布局和 `reset()` 必须先将比例限制在配置范围内；边界覆盖所需的有效下限高于配置上限时，边界规则优先，并将有效上限提升到该有效下限。
- **FR-007**：组件必须公开 `flipHorizontal()` 和 `flipVertical()` 实例方法，每次调用切换对应方向的翻转状态。
- **FR-008**：水平和垂直翻转必须相对屏幕可见方向执行，并以图片显示中心为翻转中心。
- **FR-009**：翻转不得改变图片当前缩放比例、旋转角度或裁剪框尺寸。
- **FR-010**：实时预览、裁剪框预览、base64/Blob 导出必须与当前翻转状态一致。
- **FR-011**：`change` 事件的 `image` 状态必须新增 `flipX` 和 `flipY` 布尔字段，并在翻转后触发。
- **FR-012**：`reset()` 必须同时清除水平和垂直翻转状态，现有旋转、缩放和裁剪框重置语义保持不变。
- **FR-013**：组件必须公开同步读取方法 `getCropCoordinates()`，返回 `points`、`boundingBox`、`source` 和 `transform`；`points` 按裁剪框左上、右上、右下、左下顺序给出源图像素坐标，`transform` 包含 `rotate`、`flipX` 和 `flipY`。
- **FR-014**：`getCropCoordinates()` 必须正确反映移动、缩放、任意角度旋转和水平/垂直翻转的组合结果。
- **FR-015**：调用 `getCropCoordinates()` 不得改变组件状态，也不得触发 `change`、`real-time` 或图片导出。
- **FR-016**：没有已加载图片时，`getCropCoordinates()` 必须返回 `null`。
- **FR-017**：新增 API 必须提供类型声明、直接回归测试、中英文文档，并在首页或全功能配置页提供操作示例。
- **FR-018**：未配置新 props、未调用新方法时，现有缩放、旋转、边界、预览、导出和事件行为必须保持不变。

### 关键实体

- **缩放范围**：由绝对最小比例和绝对最大比例组成，约束所有用户与公开缩放入口。
- **图片变换状态**：现有位置、缩放、旋转状态，加上水平和垂直翻转状态。
- **原图裁剪几何**：裁剪框经过当前全部图片变换反向映射后，在完整源图像素坐标系中的区域描述。

## 成功标准

### 可衡量结果

- **SC-001**：对每个缩放入口连续执行 100 次越界操作，最终缩放比例均有 100% 的次数停留在允许范围内。
- **SC-002**：任意水平/垂直翻转组合均可通过最多两次同向操作恢复原方向，预览、导出和状态中的方向一致率为 100%。
- **SC-003**：在移动、缩放、任意角度旋转和翻转的覆盖组合中，返回的原图几何点与预期源图像素坐标逐点误差不超过 0.01 像素。
- **SC-004**：读取原图裁剪坐标前后，全部公开裁剪状态字段逐项一致，且没有新增状态事件。
- **SC-005**：未使用新能力时，现有自动化测试保持全部通过。
- **SC-006**：使用者无需解析预览 URL、HTML、CSS transform 或导出图片即可获得服务端可消费的原图裁剪几何。

## 假设

- 缩放上下限使用当前图片变换中的绝对 `scale` 值，不使用相对初始比例的倍数。
- `minScale` 和 `maxScale` 只接受正数，且 `minScale <= maxScale`；本功能不新增无效配置校验或自动修正。
- 翻转只通过实例方法切换，本期不新增默认翻转 props 或拖拽手势。
- 本期不新增通用 `setState()`、撤销栈或服务端请求；“恢复编辑”由业务保存返回的几何与现有状态信息后自行编排。
- 原图坐标以方向校正后的源图为基准，不保证直接对应带 EXIF 方向标记的原始文件字节排列。
- 原图裁剪四角点不自动限制到源图边界，外接矩形由实际四角点的最小和最大坐标计算。
