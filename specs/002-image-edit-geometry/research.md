# 技术研究：图片编辑与原图几何

## 决策 1：缩放限制使用绝对比例

**决定**：`minScale`、`maxScale` 直接约束当前 `imgAxis.scale`，默认分别为 `0.01` 和无限上限。

**理由**：与现有公开缩放状态一致，业务可直接用 `change` 中的比例配置限制，不需要额外换算初始比例。

**考虑过的替代方案**：相对初始比例倍数。该方案更适合单一图片，但同一配置在不同 `mode` 和图片尺寸下难以与现有绝对状态对应。

## 决策 2：边界覆盖形成有效缩放范围

**决定**：边界所需比例提升有效下限；若其高于配置上限，有效上限同步提升到有效下限。

**理由**：避免 `centerBox` / `centerWrapper` 与最大比例互相触发缩放、回弹循环，同时保持已有“必须覆盖”的公开语义。

**考虑过的替代方案**：最大比例绝对优先；会让已开启的边界限制失效。对冲突配置报错；会新增规格未授权的校验和错误流程。

## 决策 3：翻转矩阵位于位移与旋转之间

**决定**：CSS 变换顺序表达为统一缩放、位移、屏幕轴翻转、旋转；Canvas 以中心为原点应用等价的翻转和旋转。

**理由**：屏幕轴翻转不会反向已有位移，并且旋转后的“水平”仍对应用户看到的左右方向。

**考虑过的替代方案**：沿图片自身坐标轴翻转；旋转 90° 后按钮语义会交换。直接使用负的总缩放；会同时反向位移并破坏 `imgAxis.x/y` 约定。

## 决策 4：用逆变换返回源图四角点

**决定**：返回四个精确源图点、外接矩形、源图尺寸和变换元数据，点位不自动裁到源图边界。

**理由**：任意角度旋转后的真实裁剪区域不是轴对齐矩形，四角点可供服务端建立裁剪路径，外接矩形仍方便只支持矩形的消费者判断范围。

**考虑过的替代方案**：只返回外接矩形，会包含真实裁剪区域之外的像素；返回旋转中间图矩形，不属于用户要求的原图坐标。

## 决策 5：原图指方向校正后的源 Canvas

**决定**：坐标原点与尺寸取内部方向校正后 canvas，和预览、导出的源数据一致。

**理由**：浏览器对 EXIF 的自动处理存在平台差异，内部 canvas 是当前组件唯一稳定且可直接验证的源坐标系。

**考虑过的替代方案**：返回上传文件原始字节坐标，需要持久化 EXIF 方向并反向映射，超出本次范围。
