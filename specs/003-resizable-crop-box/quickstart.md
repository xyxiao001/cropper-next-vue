# 快速验证：可缩放裁剪框

## 前置条件

- Node.js >=22
- 已执行 `pnpm install`
- 当前功能规格和实施计划已确认

## 自动化检查

```bash
pnpm run check
pnpm run build:docs
git diff --check
```

预期结果：类型检查、全部测试、覆盖率、库构建和文档构建通过，diff 不包含空白错误。

## 场景 1：默认兼容

1. 打开未传入 `cropBoxResizable` 的现有基础 Demo。
2. 确认裁剪框没有八方向控制点。
3. 拖动图片、移动裁剪框、滚轮缩放和双指缩放。

预期结果：视觉和交互与功能实现前一致。

## 场景 2：八方向缩放

1. 打开全功能 Demo。
2. 开启“允许缩放裁剪框”。
3. 依次拖动四条边和四个角。
4. 分别使用鼠标和移动设备单指触摸验证。

预期结果：空闲时只显示连续外层边框，四角 L 形位于框外并贴住角点，四边控制提示贴在线上；开始拖动后显示四条三等分参考线，松手后参考线平滑淡出；八个方向都能调整裁剪框。

## 场景 3：边界和回弹

1. 把控制点拖到容器四周。
2. 关闭图片覆盖裁剪框模式并扩大裁剪框。
3. 记录图片状态。
4. 开启图片覆盖裁剪框模式，再次扩大裁剪框并松手。

预期结果：裁剪框始终在容器内；关闭覆盖模式时图片不被额外调整；开启后图片在松手时按照现有规则回弹并覆盖裁剪框。

## 场景 4：输出和重置

1. 缩放并移动裁剪框。
2. 查看 `change` 状态面板。
3. 获取原图裁剪坐标并导出图片。
4. 调用 `reset()`。

预期结果：状态、坐标和导出范围与当前可见裁剪框一致；重置后裁剪框恢复初始尺寸和居中位置。

## 场景 5：首页和文档

1. 打开文档站首页。
2. 确认首页体验区默认显示连续边框与八方向控制区，拖动控制区时才显示九宫格。
3. 关闭首页的裁剪框缩放开关。
4. 查看 README、指南、参数和方法说明的中英文内容。

预期结果：首页默认可以直接缩放裁剪框，关闭后九宫格与控制区一起隐藏；文档明确说明组件 prop 默认关闭、首页演示默认开启，且不存在“当前版本没有可缩放裁剪框”的冲突描述。
