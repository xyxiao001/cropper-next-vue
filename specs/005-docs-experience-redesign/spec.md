# Feature Specification: 文档站体验重构

**Feature Branch**: `codex/main-dev-20260921-2`

**Created**: 2026-09-21

**Status**: Confirmed — 用户于 2026-09-21 要求“开始重构，要求设计好看”，确认规格方向；具体计划待确认

**Input**: User description: "深入分析我们开源组件，我想把整个文档库重构，更富有设计感，用户更能懂这个"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看懂价值并完成首次裁剪 (Priority: P1)

首次访问的组件使用者能知道这个组件适合什么场景，体验裁剪，并通过完整接入示例得到第一张导出图片。

**Why this priority**: 首页和快速开始决定用户能否从“看到库”走到“成功使用库”。

**Independent Test**: 在一个已可运行的用户项目中，按首页到快速开始的路径完成图片输入、裁剪和导出，不借用文档站内部工具。

**Acceptance Scenarios**:

1. **Given** 首次访问首页，**When** 浏览首屏，**Then** 能识别图片裁剪用途，看到真实演示，并明确区分开始接入和在线体验两个入口。
2. **Given** 已按快速开始安装组件，**When** 复制完整示例并按说明提供图片，**Then** 能显示裁剪组件并获得可见导出结果，不需要补找未说明的代码或私有依赖。
3. **Given** 首页展示了区别于库默认行为的示例设置，**When** 阅读演示附近的配置说明，**Then** 能知道该设置是示例显式启用的能力。

### User Story 2 - 理解选区、边界与导出的关系 (Priority: P1)

使用者能通过解释、图示和可操作示例，理解容器、图片、裁剪框和导出结果，选择正确的配置完成业务需求。

**Why this priority**: 当前理解成本集中在多个空间概念、独立开关和导出设置的关系上。

**Independent Test**: 分别完成“固定 16:9”“让图片覆盖裁剪区域”“获取 Blob”任务，解释所选配置及预期结果。

**Acceptance Scenarios**:

1. **Given** 查看核心概念，**When** 对照图示与演示，**Then** 能区分容器与裁剪框，并区分显示尺寸、源图坐标和输出像素。
2. **Given** 查看裁剪框讲解，**When** 阅读固定比例示例，**Then** 能区分允许缩放与启用尺寸/比例约束两个开关，知道尺寸约束的单位。
3. **Given** 查看边界示例，**When** 比较无约束、覆盖裁剪框和覆盖容器三种情况，**Then** 描述与真实行为一致，并说明拖动和回弹的差别。
4. **Given** 查看导出示例，**When** 调整已有导出设置并导出，**Then** 可以观察实际格式、宽高与文件大小，理解压缩质量、预览分辨率与输出分辨率的区别。
5. **Given** 查看预览与状态讲解，**When** 选择接入方式，**Then** 能区分实时预览、状态通知、源图坐标读取和文件导出各自的用途。

### User Story 3 - 按业务场景接入并快速查阅 (Priority: P2)

已有明确需求的使用者可以从头像、文章封面、商品主图进入示例，定位所需参数、实例方法和事件。

**Why this priority**: 场景能把组件能力转化为可复用的业务方案，参考文档则服务后续维护。

**Independent Test**: 从任意场景页找到相关参数说明，从参数说明返回关联示例，检查示例的输入、操作、结果与代码是否对应。

**Acceptance Scenarios**:

1. **Given** 进入场景页，**When** 查看说明和代码，**Then** 能识别输入、关键配置与输出，并区分演示结果和需要自行接入的业务服务。
2. **Given** 查询一个公开参数、方法或事件，**When** 从相应分组定位它，**Then** 获得准确名称、用途、取值或调用方式、默认行为以及相关示例。
3. **Given** 查看长文档，**When** 使用本页目录或下一篇入口，**Then** 能直接到达目标章节或建议的下一步。
4. **Given** 通过现有 20 个路由中的任意一个进入网站，**When** 页面加载，**Then** 对应内容仍可直接访问。

### User Story 4 - 在一致、清晰的界面中阅读与操作 (Priority: P2)

使用者在首页、文档、场景和工作台之间切换时，能识别一致的品牌、导航和操作方式，并在中文、英文和窄屏下完成核心路径。

**Why this priority**: 设计感需要体现为稳定的层级、阅读节奏与操作反馈，而不仅是首页装饰。

**Independent Test**: 检查四类页面的标题、正文、代码、控件与结果呈现；分别在中文和英文完成导航、阅读、演示和复制。

**Acceptance Scenarios**:

1. **Given** 访问四类页面，**When** 对照视觉呈现，**Then** 色彩、文字层级、间距、控件与代码展示规则一致，首页和工作台允许符合任务的不同布局。
2. **Given** 使用英文界面，**When** 查看演示工具栏与代码操作，**Then** 不出现遗漏翻译的固定中文功能标签；切换语言后仍停留在同一主题。
3. **Given** 使用窄屏设备，**When** 打开导航、阅读正文与操作示例，**Then** 内容和操作不会被裁切，代码和表格可在自身区域滚动。
4. **Given** 使用键盘，**When** 操作站点导航、目录和代码工具栏，**Then** 可以到达操作目标、看到焦点并执行对应操作；不扩展裁剪组件本身的键盘交互能力。

### Edge Cases

- 演示配置不同于组件默认值：以显式的演示配置说明消除歧义，不更改库默认值。
- 固定比例或宽高限制存在前置开关：文档明确写出前提与适用入口，不为库新增参数校验或自动修正。
- 初始布局与覆盖边界同时设置：解释前者确定初始呈现，后者约束可用状态；具体规则以现有行为为准。
- 放大、设备像素比和最长边限制使输出尺寸区别于裁剪框显示尺寸：报告真实结果，不用显示宽高冒充导出像素。
- 圆形头像预览：明确当前导出仍为方形，不宣传圆形文件导出能力。
- 没有已加载图片时读取源图坐标：描述已有返回行为，不增加新拦截或提示。
- 英文标题、长参数名和长代码：保持可读和可操作，不扩大整个页面的横向宽度。
- 图片加载或导出失败：保持已有处理，不新增重试、备用图片、错误吞掉或降级分支。
- 库类型声明与运行时存在差异：核实并记录内容边界，不在文档重构中顺带修改库的公开契约。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 首页必须说明组件用途，展示真实裁剪效果，并提供目的不同的接入与在线体验入口。
- **FR-002**: 导航必须区分入门、概念、场景、功能示例与 API 查阅；保留现有内容和全部 20 个页面的直接访问入口。
- **FR-003**: 快速开始必须给出安装、引入组件与样式、提供图片、显示选区、执行导出、查看结果的完整路径；示例不得依赖未提供的文档站内部模块。
- **FR-004**: 概念讲解必须覆盖容器、图片、裁剪框、导出结果之间的关系，并明确显示尺寸、源图坐标与输出像素的区别。
- **FR-005**: 裁剪框、边界和导出三个重点主题必须使用图示或有标注的可操作示例，解释前置条件、操作与可见结果。
- **FR-006**: 每个功能示例必须提供用途、操作引导、结果说明、可查看和复制的接入代码及关联参考入口；说明代码所需依赖与图片来源。
- **FR-007**: API 参考必须按用途分组，完整覆盖当前 30 个参数、16 个公开方法、5 个事件名及已有插槽用途；准确描述默认值、单位、前置条件和返回内容，区分保留字段、别名与推荐用法。
- **FR-008**: 头像、封面与商品图三个现有场景必须说明适用目标、关键配置、实际结果和接入方式；不得把业务方服务、圆形预览或示例控件描述为组件内置能力。
- **FR-009**: 现有全功能工作台必须保留编辑、配置、方法调用、状态/坐标读取和导出能力，并统一到站点的视觉和术语体系中。
- **FR-010**: 首页、文档、场景、工作台必须采用一致的品牌元素、文字层级、色彩角色、间距、控件和代码样式；布局分别适合展示、阅读与编辑任务。
- **FR-011**: 长文档必须提供本页目录与章节定位，学习页面必须给出下一步阅读入口，主题与关联示例之间可相互到达。
- **FR-012**: 中文和英文必须覆盖相同的核心内容和功能标签；语言切换保留当前主题和已有语言偏好行为。
- **FR-013**: 在 375px、768px、1440px 宽度下，正文、导航和关键操作必须完整可用；长代码和宽表格可在局部滚动。
- **FR-014**: 文档站导航、目录和代码工具栏必须支持键盘访问及可见焦点；不得以纯色差作为唯一状态说明。
- **FR-015**: 演示中区别于库默认值的配置必须明确标注；所有技术讲解必须以当前公开实现为依据，发现文字误导时修正文档，不修改库行为来迎合文案。
- **FR-016**: 重构必须限定在文档结构、视觉、内容与演示呈现，不改变库的公开 API、默认值、裁剪几何、交互算法、事件时机和导出规则，也不增加兜底、校验、重试或降级行为。

### Key Entities

- **学习主题**：面向一个明确问题，包含解释、示例和下一步阅读关系。
- **示例**：包含用途、图片输入、显式配置、操作、实际结果和接入代码。
- **参考条目**：记录公开名称、用途、默认值或调用规则、单位与关联主题。
- **业务场景**：将既有能力组合为头像、封面或商品图使用路径。
- **语言版本**：同一主题的中文与英文内容，共享其含义和访问关系。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 邀请 3 位具有基础 Vue 开发经验但未使用本库的读者，在不提供口头解释的情况下，至少 2 位能在浏览首页 30 秒后说出组件用途、两个业务场景及开始接入入口。此项需要真实读者验收，未开展时必须标为待验收。
- **SC-002**: 在既有可运行项目和正常安装条件下，同一组读者至少 2 位能仅按快速开始在 5 分钟内完成首次裁剪导出；不计依赖下载安装耗时。未开展时不得宣称通过。
- **SC-003**: “固定 16:9”“获得 Blob”“让裁剪区域不留白”三项任务，均能从首页或全站导航经过不超过 2 次页面跳转到达直接相关说明。
- **SC-004**: 20 个现有页面入口全部可用；30 个参数、16 个方法、5 个事件名及已有插槽用途均有准确对应的参考或示例说明。
- **SC-005**: 快速开始及三个场景的接入代码经过独立复现，不依赖文档站内部组件或工具；涉及业务服务的扩展代码明确标明替换点，首次裁剪导出不依赖真实服务。
- **SC-006**: 首页、快速开始、三个重点主题、三个业务场景与工作台的中英文关键操作均可完成；站点公共功能标签无遗漏翻译。
- **SC-007**: 在三种目标宽度下检查全部页面，无正文裁切或整页横向溢出；导航、目录、代码工具栏均可通过键盘操作。
- **SC-008**: 对照现有能力清单完成验收，文档重构没有删除既有演示能力，也没有改变组件公开行为；四类页面逐项符合已确认的文字、色彩、间距和控件规范。

## Assumptions

- 主要读者为需要在已有应用中接入图片裁剪的开发者；新手与已集成用户需要不同的阅读路径。
- “整个文档库”指现有文档与示例站的整体重构，包含中英文、首页、参考文档、场景页和全功能工作台，不包含重新设计 npm 库 API。
- 视觉方向为“有品牌感的产品官网 + 清晰的开发者文档”，用户强调设计好看；具体视觉方案通过设计稿与实施计划呈现。
- 保留既有双语、图片数据来源、图片读取方式、上传/导出的请求时机和异常处理；调整的是讲解、组织和展示。
- 不引入账户、云端上传、搜索服务、在线代码执行器、AI 问答、多图处理、额外语言、配置持久化或自动降级功能。
- 不将框架迁移、深色主题或新品牌 logo 作为默认需求；技术实现选择在规格确认后进入计划阶段。
- 真实读者可用性验收需用户协助安排；源码检查和浏览器检查不能替代该项结果。
- 规格与后续计划均按仓库要求经用户确认；当前阶段仅交付分析、规格和规格质量检查。
