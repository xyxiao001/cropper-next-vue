# 文档站审视与重构方向

日期：2026-09-21。基线：`28fa969`，分支 `codex/main-dev-20260921-2`。

这是需求确认前的分析与设计建议，不是已经批准的实施计划。分析依据为当前仓库源码、全部页面的目录与主要内容、首页和参数页的浏览器检查；没有进行用户访谈或完整的跨设备测试，以下学习障碍属于专家评估，不能当作已测得的用户数据。

## 1. 组件究竟提供什么

当前公开入口有 **30 个 props、16 个实例方法、5 个事件名（包含一个实时预览别名）**。文档站有 **20 个页面：首页、5 个文档页、3 个场景页、11 个功能示例页**。

真正值得展示的价值是：让开发者把可操作、可预览、可导出的图片裁剪嵌入自己的业务页面，并能控制图片与裁剪区域的几何关系。当前能力足以支撑头像、封面和商品图三条完整的学习路径。

| 能力 | 用户能完成的事 | 源码依据 | 应如何讲解 |
| --- | --- | --- | --- |
| 图片布局和交互 | 放入图片，拖动、缩放，选择初始布局 | `lib/vue-cropper.vue`、`useImagePipeline.ts`、`useInteractions.ts`、`useWheelZoom.ts` | 先区分容器、图片、裁剪框，再谈布局模式与缩放锚点 |
| 裁剪框 | 调整位置、八方向缩放、固定比例与宽高限制 | `useCropLayout.ts`、`useCropResize.ts` | 分开解释“允许拖动缩放”和“启用比例/尺寸限制”，两者是独立开关 |
| 旋转与翻转 | 任意角度旋转、90°旋转、水平/垂直翻转、重置 | `usePublicMethods.ts` | 用构图前后对比解释；区别 `reset()`、`rotateClear()`、`reload()` |
| 覆盖边界 | 防止裁剪区域或整个工作区露出图片外部 | `useInteractions.ts`、`common.ts` | 用“覆盖裁剪框 / 覆盖容器”表示空间关系，展示旋转后的效果 |
| 导出 | 得到 base64 或 Blob，设置格式、质量、像素规模 | `useExport.ts`、`common.ts` | 分开解释格式、压缩质量、输出尺寸；让用户看到实际结果 |
| 预览和状态 | 在头像或卡片中同步显示结果，读取编辑状态 | `useRealTime.ts`、`useCropState.ts` | `real-time` 用于预览，`change` 用于状态观察，导出是独立动作 |
| 源图坐标 | 获得四个裁剪角点和包围盒 | `useCropCoordinates.ts` | 明确与容器坐标的区别，适合已有集成需求的进阶读者 |
| 集成入口 | 图片拖入、加载插槽、滤镜函数、局部/全局组件注册 | `useDragUpload.ts`、`vue-cropper.vue`、`index.ts` | 展示如何接入业务；文档演示的模拟上传与真实服务接口分开说明 |

### 需要优先建立的四个概念

1. **容器**：编辑工作区，决定用户在哪个区域操作。
2. **图片**：在工作区中移动、缩放、旋转的内容。
3. **裁剪框**：最终选取哪一块内容；其显示大小不等于导出像素大小。
4. **导出结果**：按当前选区和导出设置生成的图片文件或数据。

容器坐标、源图坐标和输出像素是三个不同的量。先用标注图解释这件事，比让用户从参数表自行推断更有效。

| P1 | `outputSize`、`full`、`original`、`maxSideLength`、`previewMaxSide` 集中在参数表和长说明中 | 容易把压缩质量、预览分辨率与导出像素混为一谈 | 导出章节用显示大小、实际导出宽高、格式和文件大小串起这些参数 |

| P2 | 侧栏按“文档 / 真实场景 / 示例”分组；方法、变更记录、事件混排 | 学习者与查阅者共用一套没有先后关系的入口 | 分为入门、核心概念、场景实践、功能示例、API 参考 |

| P2 | 基础、边界、导出等例子使用固定 480px 宽度，移动端外层还有内边距 | 存在窄屏溢出的明确风险；尚未完成全页实机复现 | 在文档展示层适配窄屏，并单独说明示例布局，不修改库内几何算法 |
| P2 | 普通示例、场景示例和全功能工作台拥有不同外壳和代码展示方式 | 用户每换一个页面都要重新判断哪里操作、哪里看结果 | 统一页面层级、演示/解释/代码/参考入口的位置 |
| P3 | 首页展示 hash 路由、仓库构建等维护者信息 | 抢占面向使用者的首屏注意力 | 将仓库维护信息移到次要的开发说明区域 |

### 内容准确性需要在重写时逐项核对

- `Methods.md` 将 `getCropData(type?)` 概括为 `Promise<string>`，而实际传 `'blob'` 会返回 Blob；默认返回字符串，专用 `getCropBlob()` 返回 Blob。应明确区分调用签名。
- `original` 不宜笼统说成“按当前缩放倍数放大”。当前裁剪导出逻辑用裁剪尺寸除以图片缩放比例，再考虑设备像素比与最长边限制。应以简单数值例子说明，例如关闭高分屏且不触发最长边限制时，200px 选区、图片缩放 0.5，对应约 400px 的源图输出宽度。
- `mode` 文档与运行时支持的布局取值，应与导出的声明类型一起核对。入口类型目前引用 `InterfaceModeHandle` 的键，其声明包含 `contain/cover/default`，与文档列出的 `original` 和长度字符串有差异。这是库类型问题线索，本轮只记录，不顺带修改公开类型。
- `color` 是保留字段，不能作为已生效的主题能力宣传；真正控制裁剪框描边的是 `cropColor`。
- 圆形头像是场景中的圆形展示，当前导出仍为方形图片；“上传”演示不能描述成库提供了服务端上传能力。
- `getCropCoordinates()` 返回方向校正后的源图空间角点；旋转后四角不等于轴对齐包围盒，点位也不自动裁到源图边界。

## 3. 建议的信息架构

首页负责展示价值和引导行动，文档负责学习和查阅，工作台负责组合验证。全站共享品牌与语言入口，页面可拥有适合任务的宽度。

| 导航层级 | 内容 | 对应当前内容 |
| --- | --- | --- |
| 首页 | 一句话定位、可操作裁剪预览、三类业务结果、接入入口 | `/` |
| 开始使用 | 安装、完整首次裁剪、基本概念 | `/guide`、`/demo-basic`，补充核心概念讲解 |
| 核心概念 | 容器与选区、布局与覆盖边界、交互与程序控制、预览与导出、状态与源图坐标 | 由现有参数与示例中的解释重组，不新增库能力 |
| 场景实践 | 头像上传、文章封面、商品主图 | 三个 `/scenario-*` |
| 功能示例 | 裁剪框、边界、旋转、预览、导出、上传、加载、滤镜、几何编辑 | 保留各 `/demo-*` 可直接访问 |
| API 参考 | 参数、实例方法、事件、已有插槽说明 | `/props`、`/methods`、`/event` 及加载/拖入示例 |
| 在线工作台 | 完整编辑画布、分组设置、状态与导出结果 | `/demo-all` |
| 版本记录 | 当前已有版本信息 | `/changelog` |

文档之间建立“现在要解决的问题 → 相关示例 → 精确 API”的链接。保留现有 20 个路由直接可达；不依靠重定向或兼容兜底去掩盖页面缺失。

参数建议分成图片与布局、交互与缩放、裁剪框约束、覆盖边界、导出与预览、外观与扩展六组。每项保留名称、用途、默认值、类型/取值、单位、前置开关与关联示例。

## 4. 视觉方向草案

建议采用“图像编辑产品官网 + 开发者文档”。风格偏明亮、精确、有留白，让裁剪图像与结果本身成为视觉主体。该风格仍待用户确认。

- **品牌元素**：使用裁剪四角、九宫格和边界线作为局部装饰；沿用项目名称，不发起独立 logo 重塑。
- **色彩建议**：暖白底 `#F7F8F5`、石墨文字 `#18211F`、深绿主操作 `#176C52`，浅绿用作选择状态。具体对比度与控件状态在设计阶段验证。
- **版式**：首页使用更大的标题与真实裁剪画面；正文限制阅读宽度；工作台按编辑器任务使用较宽布局。
- **层级**：主体内容依靠字号、字重、留白和细边线区分；提示、代码、实时结果有各自稳定的样式。
- **动效**：用于切换和操作反馈；无需持续播放装饰动画。交互先保证文字和静态状态能表达清楚。
- **内容语气**：先说“你想得到什么”，再说“需要设置什么”。例如“让封面始终铺满选区”，再引入 `centerBox`。

## 5. 示例如何真正教会用户

每个功能页至少回答五件事：**解决什么问题、先做哪个动作、应看到什么变化、复制哪段代码、下一步查什么参数**。

三条关键教学线：

1. **边界**：对比无约束、覆盖裁剪框、覆盖容器；配同类图片及目标区域标注，解释旋转后的覆盖。准确区分初始布局与持续边界约束。
2. **比例**：先体验自由裁剪，再开启固定比例；明确启用约束与允许缩放是两件事。宽高限制标明容器像素，不等同于输出分辨率。
3. **导出**：对照显示选区尺寸与实际图片像素；质量、DPR、原图比例和最长边各解释一个职责。页面使用真实导出结果，避免以静态数字模拟行为。

已有工作台保留复杂组合能力，用分组和就近解释降低找配置的成本。首轮不额外做在线代码执行器、分享链接、配置存储、AI 问答、云端上传或多图批处理。

## 6. 技术上的判断与边界

现有 Vue 页面、Markdown 演示和语言切换已经能承载这些内容，重构文档不必先迁移框架。`DemoAll.vue`、三个场景页与 `CropExportPanel.vue` 是可保留的资产。

需要评估的文档层维护问题包括：路由和侧栏分别声明；示例代码与执行脚本重复；中英文标签散布在页面；多套样式缺少一致性。实现方案阶段再决定整理方式，此刻不做架构承诺。

此次建议范围为文档站结构、视觉、内容与演示呈现，库的 API、默认值、裁剪算法、事件时机、异常处理、网络请求和导出规则保持原有契约。不增加兜底、拦截、校验或自动修正。上述类型差异等库问题仅记录；如需修复，单独明确授权。

## 8. 如何验收“更容易懂”

- 已有 Vue 开发基础的首次使用者，在既有可运行项目中按快速开始于 5 分钟内完成首次裁剪导出；这是待验证目标，不是已获得的数据。
- 不读全部参数表，也能找到“固定 16:9”“导出 Blob”“避免裁剪区留白”三项任务的入口。
- 给出容器尺寸、选区尺寸与导出结果，读者能说明三者为何不一定相等。
- 20 个现有页面入口保留，公开 API 文档完整，中文与英文的关键路径同等可用。
- 在 375px、768px、1440px 的目标视口检查阅读、导航、示例与代码；正文不被裁切，横向滚动限定在代码/表格内部。
