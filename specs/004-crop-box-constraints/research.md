# 技术调研：裁剪框比例与尺寸限制

## 决策 1：使用一个开关和五个标量 prop，而不是约束对象

**决定**：公开 `cropBoxConstraintsEnabled`、`cropAspectRatio`、`minCropWidth`、`minCropHeight`、`maxCropWidth`、`maxCropHeight`。

**理由**：项目现有 `minScale`、`maxScale` 等范围能力采用标量 prop；独立 prop 在 Vue 模板、类型提示和参数表中更直接，也便于 Demo 单独操控。

**考虑过的替代方案**：增加 `cropConstraints` 对象。该方案会引入新的嵌套配置结构和对象更新语义，超出当前组件 API 风格。

## 决策 2：开关开启后统一约束全部尺寸入口

**决定**：开关关闭时保持现有行为；开启时约束拖动、首次及运行时 `cropLayout`、`setCropLayout()` 和 `reset()`。

**理由**：用户确认所有尺寸入口必须遵循同一限制，避免程序化设置的超限裁剪框在首次拖动时突变；默认关闭保证现有调用方兼容。

**考虑过的替代方案**：只限制初始 `cropLayout`，或只限制 prop 而不限制公开方法。两者都会在其他尺寸入口后保留相同突变问题。

## 决策 3：比例约束统一换算为一个尺寸区间

**决定**：固定比例时把高度约束换算成宽度约束，并与横纵容器空间求交集；夹取宽度后通过比例派生高度。

**理由**：单一尺度可以保证宽高比例精确一致，避免先夹宽再夹高造成二次破坏比例。

**考虑过的替代方案**：先独立夹取宽高，再在最后修正比例。该方案可能让最后修正后的另一维重新越过尺寸或容器边界。

## 决策 4：边控制器围绕另一维中心对称变化

**决定**：左右边保持对应对边不变，高度围绕纵向中心变化；上下边保持对应对边不变，宽度围绕横向中心变化。

**理由**：这是用户确认的交互规则，能保留八方向操作，同时让主拖动方向和固定锚点清晰可预测。

**考虑过的替代方案**：固定比例时禁用边控制器，或让另一维单侧增长。两种方案均与已确认行为不符。

## 决策 5：角控制器由变化更明显的轴驱动

**决定**：把横向候选宽度和纵向候选高度换算后的宽度进行比较，使用相对起始宽度变化量更大的候选。

**理由**：角拖动同时产生横纵输入，选择变化更明显的轴可以响应用户主要拖动方向，并避免固定使用某一轴时出现明显脱手感。

**考虑过的替代方案**：始终由水平或垂直轴驱动。实现更简单，但另一方向的大幅拖动不会影响结果。

## 决策 6：约束在会话开始时快照

**决定**：每次按下控制器时读取当前 prop，一次拖动期间不再切换约束。

**理由**：可以保证同一次手势的几何规则稳定，也符合规格中“下一次拖动使用新配置”的边界要求。

**考虑过的替代方案**：每次移动读取最新 prop。运行时切换比例会使同一次拖动突然跳变。

## 决策 7：不处理无可行解的配置

**决定**：调用方必须传入正数、连贯的最小/最大值，并保证约束与当前容器存在可行尺寸；组件不新增校验、自动纠错、交换值或错误提示。

**理由**：项目全局规则禁止未经授权增加兜底和校验，规格也已明确调用方责任。

**考虑过的替代方案**：自动交换最小/最大值、忽略无效比例或回退自由缩放。这些都会形成未授权的额外行为。

## 决策 8：复用现有输出链路

**决定**：只扩展 `calculateCropResize()` 的最终几何，不新增约束状态事件或输出字段。

**理由**：现有 `change.crop`、实时预览、导出与原图坐标已经消费最终裁剪框，约束后的结果会自然同步。

**考虑过的替代方案**：新增约束状态字段或专用事件。需求没有要求，会扩大公开契约。

## 决策 9：程序化比例框在请求范围内取最大值

**决定**：请求宽高与固定比例不一致时，先取完全位于请求矩形内的最大目标比例框，再应用最小/最大尺寸与容器形成的可行区间。

**理由**：不会因为固定比例而意外放大任一请求边；只有请求结果低于明确配置的最小尺寸时，才按比例扩大到最小可行尺寸。

**考虑过的替代方案**：始终宽度优先或高度优先。两者都会在部分宽高组合中放大另一维，偏离“阻止超限设置”的目标。

## 决策 10：有效裁剪尺寸作为程序化入口的统一结果

**决定**：保留 `innerCropLayout` 的原始输入，通过 `effectiveCropLayoutStyle` 统一计算实际尺寸，并让现有渲染、状态、导出和坐标链路继续读取该结果。

**理由**：可以同时支持数字、像素和百分比输入，不改变公开方法签名，也避免在 watcher、重置和方法中复制约束算法。

**考虑过的替代方案**：在每个写入入口分别改写 `innerCropLayout`。该方案会重复解析和约束逻辑，并可能让同一输入在不同入口得到不同结果。

## 决策 11：仅在限制开关开启瞬间重新居中

**决定**：运行时从关闭切换为开启裁剪框限制时，应用最新有效尺寸并重新计算容器中心；限制已开启后的比例或尺寸参数更新继续保留当前位置。

**理由**：从无限制的大裁剪框切换到受限小裁剪框时，旧坐标通常对应左上角或旧尺寸锚点，继续沿用会让裁剪区域偏离视觉中心；重新居中符合用户明确要求，同时将坐标变化限定在单一开关转换时刻。

**考虑过的替代方案**：所有约束参数变化都重新居中。该方案会让用户调整最大尺寸或比例时丢失当前构图位置，超出本次要求。
