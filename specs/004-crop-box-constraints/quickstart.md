# 快速验证：裁剪框比例与尺寸限制

## 前置条件

- Node.js >=22
- 已执行 `pnpm install`
- 当前规格和实施计划已确认

## 自动化检查

```bash
pnpm run check
pnpm run build:docs
git diff --check
```

预期结果：类型检查、全部测试、覆盖率、库构建、文档构建和 diff 检查通过。

## 场景 1：默认兼容

1. 保持 `cropBoxConstraintsEnabled = false`，同时传入一组比例和最小/最大尺寸参数。
2. 依次拖动四边和四角。
3. 调用 `setCropLayout()` 后执行 `reset()`。

预期结果：裁剪框继续自由缩放，最小操作尺寸仍为 `24px`，最大范围仍由容器决定；初始布局、公开方法和重置结果不被约束参数改写。

## 场景 2：固定比例角缩放

1. 在全功能 Demo 中依次选择 1:1、4:3 和 16:9。
2. 分别拖动四个角，并尝试向容器四周放大。

预期结果：四个对角锚点均保持不动；宽高比误差不超过 0.1%；裁剪框不越过容器。

## 场景 3：固定比例边缩放

1. 保持 4:3 比例。
2. 依次拖动左、右、上、下四条边。

预期结果：对应对边保持不动；另一维围绕中心对称变化；裁剪框保持 4:3 且位于容器内。

## 场景 4：最小和最大尺寸

1. 配置最小宽高为 `160 × 120`，最大宽高为 `480 × 360`。
2. 先关闭比例限制，依次缩小和放大八个方向。
3. 再开启 4:3 比例重复操作。

预期结果：自由比例和固定比例结果都不会小于最小值或大于最大值；固定比例时同时满足 4:3。

## 场景 5：会话快照

1. 以 1:1 开始拖动裁剪框。
2. 在鼠标或手指尚未松开时把外部比例改为 16:9。
3. 结束当前拖动，再开始下一次拖动。

预期结果：当前拖动保持 1:1；下一次拖动使用 16:9。

## 场景 6：文档和 Demo

1. 检查 README、使用指南和参数页的中英文内容。
2. 在全功能 Demo 中开启限制，切换自由、1:1、4:3、16:9，并调整最小/最大宽高。
3. 观察状态面板、原图坐标和导出结果。
4. 打开“方法”面板，在无加减按钮的宽输入框中填写横纵坐标并应用。

预期结果：文档中的名称、默认值和范围与组件一致；Demo 不需要修改代码即可验证组合；坐标输入可正常编辑；输出链路反映实际裁剪框。

## 场景 7：程序化尺寸约束

1. 开启限制并设置比例 `1:1`、最大宽高 `240 × 240`。
2. 初始传入 `cropLayout = 480 × 320`。
3. 依次通过运行时 prop、`setCropLayout()` 传入 `300 × 200`，再执行 `reset()`。
4. 首次拖动任一控制器。

预期结果：初始实际尺寸不超过 `240 × 240`；`300 × 200` 在限制前先取 `200 × 200`，各入口和重置均输出受约束尺寸；首次拖动不发生尺寸突变。

## 场景 8：运行时开启限制后居中

1. 保持限制关闭，使用接近或覆盖容器大小的裁剪框。
2. 配置小于当前裁剪框的最大宽高。
3. 运行时开启 `cropBoxConstraintsEnabled`。

预期结果：裁剪框先应用最大尺寸，再重新位于容器中心；随后在限制保持开启时修改最大尺寸或比例，不触发额外的自动居中。
