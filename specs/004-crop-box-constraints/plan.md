# 实施计划：裁剪框比例与尺寸限制

**分支**：`codex/feature-planning` | **日期**：2026-08-21 | **规格**：[spec.md](./spec.md)

**输入**：`specs/004-crop-box-constraints/spec.md` 中已澄清的功能规格。

## 摘要

在现有八方向裁剪框缩放计算中增加一组由独立开关控制的约束：任意正数宽高比、最小宽高和最大宽高。开关关闭时保留当前行为；开启后，拖动、首次及运行时 `cropLayout`、`setCropLayout()` 和 `reset()` 均输出满足约束的实际裁剪框，避免超限初始值在首次拖动时突变。运行时从关闭切换为开启限制时，应用限制后的裁剪框重新居中。固定比例下，拖动继续使用已确认的角和边锚点规则；程序化尺寸在请求范围内取最大的目标比例框。全功能 Demo 增加限制开关、比例与尺寸范围操控，并优化裁剪框坐标输入。

## 技术设计

### 1. 公开参数

在 `lib/vue-cropper.vue` 增加以下可选 prop：

| 名称 | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `cropBoxConstraintsEnabled` | `boolean` | `false` | 是否启用整组裁剪框比例和尺寸限制 |
| `cropAspectRatio` | `number` | 未设置 | 开启限制后使用的裁剪框宽度除以高度；未设置时自由比例 |
| `minCropWidth` | `number` | `24` | 用户拖动后允许的最小裁剪框宽度 |
| `minCropHeight` | `number` | `24` | 用户拖动后允许的最小裁剪框高度 |
| `maxCropWidth` | `number` | `Infinity` | 用户拖动后允许的最大裁剪框宽度 |
| `maxCropHeight` | `number` | `Infinity` | 用户拖动后允许的最大裁剪框高度 |

- `cropBoxConstraintsEnabled = false` 时，其他五个约束参数不生效；拖动仍使用内部 `24px` 操作下限和容器最大边界。
- `cropBoxConstraintsEnabled = true` 时，约束同时作用于控制器拖动、首次及运行时 `cropLayout`、`setCropLayout()` 和 `reset()`。
- 限制开关与 `cropBoxResizable` 独立：即使禁止用户拖动，开启限制后程序化尺寸设置仍受约束。
- 不对参数增加运行时校验、自动交换、告警或兜底；文档要求调用方传入正数、最小值不大于最大值，并保证比例与当前容器存在可行尺寸。
- 不新增比例预设公共参数。常用比例只属于 Demo 的输入方式。

### 2. 约束快照

- 扩展内部裁剪缩放会话，在按下控制器时记录本次使用的比例、最小宽高和最大宽高。
- 一次拖动过程中即使外部更新 prop，当前会话仍使用开始时快照；下一次拖动读取新值。
- `calculateCropResize()` 接收该约束快照，继续以起始裁剪框和起始指针为基准计算，避免累计误差。
- 开关关闭时传入现有默认约束快照，不读取自定义比例和尺寸范围。

### 3. 自由比例尺寸限制

- 未设置 `cropAspectRatio` 时，沿用现有八方向几何。
- 水平方向将目标宽度限制在 `minCropWidth..maxCropWidth` 与当前锚点容器空间的交集内。
- 垂直方向将目标高度限制在 `minCropHeight..maxCropHeight` 与当前锚点容器空间的交集内。
- 左侧和上侧拖动继续同步更新坐标，保持对边不变；右侧和下侧拖动继续只移动对应边界。

### 4. 固定比例角控制器

- 四个角均保持对应对角的位置不变。
- 先把指针产生的水平候选和垂直候选换算到同一个宽度尺度，选择相对起始尺寸变化量更大的候选作为本次目标尺寸。
- 把最小宽高、最大宽高及横纵容器空间统一换算成允许宽度区间：高度通过 `width / cropAspectRatio` 派生。
- 夹取目标宽度后一次性得到宽高，并根据控制方向反推左上角坐标。

### 5. 固定比例边控制器

- 左右边拖动以指针的水平变化决定目标宽度，对应对边固定；目标高度由比例派生，并围绕起始裁剪框纵向中心对称展开或收缩。
- 上下边拖动以指针的垂直变化决定目标高度，对应对边固定；目标宽度由比例派生，并围绕起始裁剪框横向中心对称展开或收缩。
- 允许区间除业务最小/最大宽高外，还要包含对边方向剩余空间和中心对称维度两侧的最短容器空间，确保结果始终留在容器内。

### 6. 程序化尺寸归一化

- 在 `lib/composables/useCropResize.ts` 提供共享的纯尺寸约束函数，输入请求宽高、容器宽高和约束，输出实际像素宽高；拖动几何和程序化布局使用同一组区间规则。
- `cropBoxConstraintsEnabled = false` 时，`useCropLayout` 保持当前仅受容器边界限制的有效尺寸计算。
- 开关开启且未设置比例时，请求宽高分别夹取到最小/最大宽高与容器范围的交集。
- 开关开启且设置比例时，先在请求宽高范围内取最大的目标比例框，再把结果夹取到比例、最小/最大宽高和容器形成的可行区间；低于最小尺寸时允许按比例放大到最小可行尺寸。
- `effectiveCropLayoutStyle` 作为首次 `cropLayout`、运行时 prop 更新、`setCropLayout()` 和 `reset()` 的统一实际尺寸来源；原始输入结构和公开方法签名不变。
- watcher 改为观察实际有效尺寸，使开关、比例或尺寸范围在运行时变化后立即刷新裁剪框，且不复制第二套状态。
- `useCropperWatchers` 单独观察限制开关的关闭到开启转换：开启时调用现有无坐标参数的裁剪框渲染流程，以最新有效尺寸计算容器中心；随后实际尺寸 watcher 继续读取已居中的坐标。限制已经开启后的比例和最小/最大尺寸更新仍按现有方式保留当前坐标。

### 7. 状态与事件

- 缩放结果仍只写入 `innerCropLayout` 与 `cropAxis`，继续复用现有 `change`、`real-time`、导出和原图坐标链路。
- `setCropLayout()` 与 `reset()` 继续接收现有输入并调用现有渲染流程，但其可见结果读取已约束的有效尺寸；`setCropAxis()` 不变。
- 不新增事件或实例方法；图片覆盖回弹仍在拖动结束后执行一次。

### 8. Demo 与文档

- `src/pages/DemoAll.vue` 在“裁剪布局”区域增加“启用裁剪框限制”开关、自由/1:1/4:3/16:9比例选择及最小/最大宽高；开关关闭时保留当前裁剪器行为。
- “设置裁剪框坐标”改为标签独占一行、横纵坐标使用更宽的原生数字输入框，并通过样式移除浏览器加减控制器。
- 不新增独立 Demo 页面：现有全功能工作台已经同时展示裁剪框、状态、原图坐标和导出结果，足以验证全部组合。
- 更新 `README.md` 的中英文能力列表和最小示例。
- 更新 `src/pages/Guide.md` 的固定比例及尺寸限制用法。
- 更新 `src/pages/Props.md` 的中英文参数表、默认值、适用范围、调用方责任和组合规则。
- `src/pages/Methods.md` 更新 `setCropLayout()` 和 `reset()` 在限制开关开启时读取实际约束尺寸的说明。
- `src/pages/Guide.md` 与 `src/pages/Props.md` 补充运行时开启限制会重新居中的位置规则；不新增 Demo 控件或页面。
