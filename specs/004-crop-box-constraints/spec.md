# 功能规格：裁剪框比例与尺寸限制

**功能分支**：`codex/feature-planning`

**创建日期**：2026-08-21

**状态**：居中规则修订计划已确认

**输入**：为可缩放裁剪框增加可开关的比例限制和大小限制；限制开启后同时约束用户拖动和程序化尺寸设置，避免首次拖动突变；检查 README 与 Demo，并补充必要的操控能力。

## 用户场景与测试

### 用户故事 1：按指定比例调整裁剪框（优先级：P1）

组件使用者可以为裁剪框指定宽高比例。最终用户拖动裁剪框控制点时，裁剪框始终保持该比例；未指定比例时继续自由调整宽高。

**优先级原因**：固定比例是头像、证件照、封面图等裁剪场景的核心约束，直接决定导出结果是否符合业务要求。

**独立测试**：分别设置 1:1、4:3 和 16:9，并操作四边及四角控制点，确认裁剪框在容器范围内持续保持指定比例；关闭比例限制后恢复自由缩放。

**验收场景**：

1. **假如**未设置比例限制，**当**用户拖动任意控制点，**那么**裁剪框继续按照现有自由宽高规则变化。
2. **假如**设置了有效宽高比例，**当**用户拖动角控制点，**那么**裁剪框保持该比例并以对应对角为固定锚点。
3. **假如**设置了有效宽高比例，**当**用户拖动边控制点，**那么**对应对边保持不动，另一维围绕裁剪框中心对称变化，并持续保持指定比例。
4. **假如**运行期间切换比例，**当**用户开始下一次拖动，**那么**该次操作使用最新比例。

---

### 用户故事 2：限制裁剪框大小（优先级：P2）

组件使用者可以配置裁剪框允许的最小宽高和最大宽高，防止最终用户把裁剪区域调整得过小或过大。

**优先级原因**：尺寸边界可以保证头像、证件照和服务端裁剪的有效输出范围，并避免控制点重叠或裁剪区域超出业务规格。

**独立测试**：配置不同的最小和最大宽高，分别向内和向外拖动八个控制点，确认裁剪框准确停留在尺寸限制与容器边界共同允许的范围内。

**验收场景**：

1. **假如**配置了最小宽高，**当**用户继续缩小到限制值以下，**那么**裁剪框停留在最小允许尺寸。
2. **假如**配置了最大宽高，**当**用户继续放大到限制值以上，**那么**裁剪框停留在最大允许尺寸。
3. **假如**尺寸限制与容器边界同时生效，**当**用户向容器外放大，**那么**裁剪框停留在两类限制共同允许的最近边界。
4. **假如**比例限制与尺寸限制同时生效，**当**用户拖动控制点，**那么**最终裁剪框同时满足比例、宽高限制和容器边界。
5. **假如**外部设置的裁剪框尺寸超过已启用的最大尺寸，**当**裁剪框进入可见状态，**那么**裁剪框不会先显示超限尺寸并在首次拖动时突变，而是在设置阶段阻止产生超限结果。
6. **假如**裁剪框限制开关关闭，**当**外部传入比例或最小/最大尺寸参数，**那么**这些参数不约束裁剪框，组件保持未开启限制时的现有行为。
7. **假如**当前裁剪框未启用限制，**当**运行时突然开启裁剪框限制并导致实际尺寸变化，**那么**应用限制后的裁剪框重新位于容器中心，而不是停留在左上角或沿用旧尺寸的坐标。

---

### 用户故事 3：通过文档和示例验证限制能力（优先级：P3）

组件使用者能够在 README 和文档站中查到比例与尺寸限制的用途、默认行为和配置方式，并在全功能 Demo 中直接切换和验证这些参数。

**优先级原因**：新的裁剪约束涉及组合行为，必须提供可操作示例才能降低接入和验证成本。

**独立测试**：打开全功能 Demo，设置比例、最小尺寸和最大尺寸后直接拖动裁剪框；再对照 README 与参数文档，确认名称、默认值和行为一致。

**验收场景**：

1. **假如**用户打开全功能 Demo，**当**进入裁剪框交互设置，**那么**可以控制比例限制、最小尺寸和最大尺寸。
2. **假如**用户查阅 README 或参数文档，**当**搜索裁剪框限制能力，**那么**可以找到公开参数、默认行为、示例和组合规则。
3. **假如**用户未配置任何新增限制，**当**使用裁剪框缩放，**那么**行为与当前版本一致。
4. **假如**用户在全功能 Demo 调用设置裁剪框坐标，**当**输入横纵坐标，**那么**两个输入框具有可用宽度且不显示加减控制器。

### 边界情况

- 比例限制和尺寸限制均未配置时，保留当前自由缩放与内部最小操作尺寸。
- 最大尺寸大于容器时，容器边界仍是最终可见裁剪框的外部边界。
- 同时配置比例和宽高边界时，裁剪框只能在满足全部约束的可行尺寸范围内变化。
- 拖动到限制边界后继续向同一方向移动，不产生控制点穿越、负尺寸或容器越界。
- 比例或大小配置在一次拖动过程中发生变化时，当前拖动会话仍使用开始拖动时的配置，下一次拖动使用新配置。
- 仅在限制开关由关闭切换为开启时重新居中；限制已开启后的比例、最小/最大尺寸更新继续沿用当前裁剪框位置并按现有边界规则处理。

## 需求

### 功能需求

- **FR-001**：组件必须提供默认关闭的裁剪框限制开关；关闭时，比例和可配置最小/最大尺寸不得改变拖动或程序化尺寸设置的现有行为。
- **FR-002**：开关开启后，组件必须支持可选的裁剪框宽高比例限制；未配置比例时保持自由缩放。
- **FR-003**：比例限制必须支持任意正数宽高比，而不是只提供固定预设。
- **FR-004**：角控制点缩放时必须保持指定比例，并保持对应对角位置不变。
- **FR-005**：边控制点在比例限制下必须保持对应对边位置不变，并让另一维围绕裁剪框中心对称变化。
- **FR-006**：组件必须提供可选的裁剪框最小宽度、最小高度、最大宽度和最大高度限制。
- **FR-007**：开关关闭或未配置新增尺寸限制时，用户拖动必须继续使用当前内部最小操作尺寸，并由容器边界限制最大尺寸。
- **FR-008**：开关开启后的裁剪框结果必须同时满足比例限制、尺寸限制、正宽高和容器边界。
- **FR-009**：开关开启后，比例和尺寸限制除约束用户拖动外，还必须约束首次及运行时更新的 `cropLayout`、`setCropLayout()` 和 `reset()`，阻止这些入口产生超限裁剪框，避免首次拖动发生尺寸突变。
- **FR-010**：程序化尺寸不符合固定比例时，组件必须在请求宽高范围内取最大的目标比例框；若该结果低于已启用的最小尺寸，再按比例扩大到满足最小限制的可行尺寸。
- **FR-011**：拖动过程中必须继续触发现有结构化 `change` 事件，且事件中的裁剪框数据必须是应用限制后的实际结果。
- **FR-012**：导出、实时预览、原图裁剪坐标和重置链路必须继续读取当前实际裁剪框，不新增独立状态来源。
- **FR-013**：全功能 Demo 必须提供是否开启裁剪框限制的开关、自由/常用比例选择、最小宽高和最大宽高操控项，并能直接验证组合结果。
- **FR-014**：README、使用指南和参数文档必须同步说明新增公开参数、默认值、交互范围和组合规则。
- **FR-015**：本功能不得改变 `cropBoxResizable` 的公开默认值、九宫格显示时机、控制器样式、图片拖动、图片缩放或图片边界回弹规则。
- **FR-016**：本功能不得新增比例预设的独立公开 API、键盘调整、裁剪框旋转或新的错误提示机制。
- **FR-017**：全功能 Demo 的“设置裁剪框坐标”必须使用无加减控制器的横纵坐标输入框，并提供足够的可输入宽度。
- **FR-018**：运行时将 `cropBoxConstraintsEnabled` 从 `false` 切换为 `true` 时，组件必须在应用最新比例和尺寸限制后将裁剪框重新居中；该规则不得改变限制已开启后的参数更新、拖动会话或 `setCropAxis()` 的坐标语义。

### 关键实体

- **裁剪框比例约束**：裁剪框宽度与高度之间必须保持的数值关系；未设置时表示自由比例。
- **裁剪框尺寸约束**：裁剪框在容器坐标系中允许的最小宽高和最大宽高。
- **约束缩放结果**：一次手柄拖动经过比例、尺寸和容器边界共同计算后的裁剪框位置与尺寸。

## 成功标准

### 可衡量结果

- **SC-001**：对 1:1、4:3 和 16:9 三种比例执行全部受支持控制点操作时，最终宽高比误差均不超过 0.1%。
- **SC-002**：在八个方向的最小值、最大值和容器边界测试中，100% 的结果位于允许范围内且保持正宽高。
- **SC-003**：比例与尺寸限制同时启用时，自动化测试覆盖角控制点、边控制点、四个容器边界及最小/最大尺寸组合。
- **SC-004**：裁剪框限制开关关闭时，现有裁剪框缩放和程序化尺寸设置测试 100% 通过，用户可感知行为不变。
- **SC-005**：全功能 Demo 可以在不修改代码的情况下完成自由比例、1:1、4:3、16:9及最小/最大宽高的交互验证。
- **SC-006**：README、使用指南和参数文档中的新增参数名称、默认值和示例与组件公开接口一致。
- **SC-007**：限制开关开启时，初始及运行时 `cropLayout`、`setCropLayout()` 和 `reset()` 产生的实际裁剪框 100% 满足已配置限制，首次拖动不发生尺寸突变。
- **SC-008**：从关闭切换为开启限制后，裁剪框中心与容器中心的横纵坐标误差均不超过 0.5 像素。

## 假设

- 比例使用“宽度 ÷ 高度”的正数表示；Demo 可以提供常用比例选项，但组件公开能力接受任意正数。
- 尺寸限制使用裁剪容器坐标系中的像素值，不支持百分比或其他长度单位。
- 不新增运行时配置校验、自动纠错、告警或降级逻辑；调用方负责传入正数且相互一致的限制值。
- 裁剪框限制开关与 `cropBoxResizable` 相互独立；前者控制约束是否生效，后者只控制用户是否能拖动裁剪框控制器。
- 本次不改变裁剪框整体移动与图片变换模型。

## Clarifications

### 2026-08-21

- 问：固定比例时，四条边控制器如何联动另一维尺寸？
  答：保留四条边控制器；拖动边时保持对应对边不动，另一维围绕裁剪框中心对称变化。
- Q: 启用裁剪框限制后，哪些尺寸设置入口需要阻止超限结果？ → A: `cropLayout`（首次和运行时）、`setCropLayout()` 和 `reset()` 全部应用限制。
- Q: 程序化设置裁剪框时，应应用哪些已启用限制？ → A: 固定比例、最小宽高和最大宽高全部应用。
- Q: 是否需要单独控制整组裁剪框限制？ → A: 增加默认关闭的公开开关，并在全功能 Demo 提供同一开关。
- Q: 程序化传入的宽高不符合固定比例时，应如何确定最终尺寸？ → A: 在请求宽高范围内取最大的目标比例框。
- Q: 运行时突然开启裁剪框限制时，应用限制后的裁剪框位置如何处理？ → A: 重新放到容器中心；只在开关由关闭切换为开启时触发。
