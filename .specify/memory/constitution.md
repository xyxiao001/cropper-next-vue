# cropper-next-vue 项目章程

## 核心原则

### 一、严格控制需求范围（不可违反）

- 只实现用户或已确认规格明确要求的行为。
- 未经授权，不新增兜底、兼容分支、额外校验、自动重试、错误吞掉、重构或体验优化。
- 提交前必须检查 diff，移除所有超出需求的改动。

### 二、保持公开 API 兼容

- `lib/` 是 npm 包的公开实现，prop、事件、实例方法和默认值都属于公开契约。
- 新增可选能力必须默认保持原有行为；破坏性变更必须在规格中明确说明。
- 公开 API 变更必须同步类型、测试和中英文文档。

### 三、保证裁剪几何与交互正确

- 修改缩放、旋转、位移或边界逻辑前，必须明确所使用的坐标系。
- 鼠标、触摸、旋转、`centerBox` 和 `centerWrapper` 只验证规格涉及的组合。
- 未被需求点名的缩放速度、事件时机、回弹时机和输入方式必须保持不变。

### 四、测试和文档必须同步

- 新行为必须有最小且直接的回归测试。
- 库代码变更必须通过 `pnpm run check`。
- 文档站或示例变更必须额外通过 `pnpm run build:docs`。
- 不提交 `dist/`、`docs-dist/`、覆盖率产物或临时调试文件。

### 五、先规格后实现

- 新增公开 API、交互模式、几何行为或跨模块功能时，必须使用 spec-kit。
- `spec.md` 和 `plan.md` 必须经过确认后才能进入实现。
- 实现阶段只执行已确认任务；发现新的范围决策时必须返回规格阶段。

## 技术约束

- Node.js `>=22`，包管理器为 `pnpm@9.15.9`。
- 技术栈为 Vue 3、TypeScript、Vite 和 Vitest。
- `lib/` 存放发布代码，`src/` 存放文档和示例站。
- `imgAxis.x/y` 表示缩放后图片左上角坐标；修改几何逻辑时必须保持该约定，除非规格明确要求迁移。
- 修改版本号、创建 tag、推送远端或发布 npm 必须获得用户明确授权。

## 开发流程

1. `$speckit-specify`：用中文定义目标、范围、用户场景和验收标准。
2. `$speckit-clarify`：只处理会影响范围或体验的关键歧义。
3. 确认规格后执行 `$speckit-plan`，再执行 `$speckit-tasks` 和 `$speckit-analyze`。
4. 确认计划和任务后执行 `$speckit-implement`。
5. 使用 `$speckit-converge` 检查实现与规格是否一致。
6. 交付前运行所需检查、复核 diff，并说明测试和提交状态。

## 治理

本章程约束所有 spec-kit 规格、计划和实现。`AGENTS.md` 的执行规则必须与本章程一致。
